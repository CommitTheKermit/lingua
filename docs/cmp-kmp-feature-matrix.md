# Flutter, Android 프로토타입, CMP/KMP 기능 대조표

## 기준

- Flutter는 복사 대상이 아니라 기존 동작을 확인하는 기준으로 사용한다.
- Android 프로토타입 회수본은 `recovery/android-prototype` 브랜치다.
- CMP/KMP 리더는 로그인 없이 TXT 문서를 열고 모든 읽기 상태를 공통 문장 인덱스로 관리한다.
- 사전의 목표 구조와 검증 기준은 `docs/cmp-kmp-dictionary-plan.md`를 따른다.

## 이식 우선순위

1. `SentenceSplitter`, 문장 인덱스 이동 상태와 `commonTest`
2. Android와 iOS TXT 문서 선택기
3. 적응형 CMP 읽기 화면
4. 검색, 위치와 입력 복원, CSV
5. 뷰어, 북마크, 표시 설정
6. 오프라인 사전과 사용자 선택형 온라인 보완

## 객체지향 주의

- Flutter `ReadScreen`은 UI, 파일 I/O, 번역, 타이머와 상태를 함께 다뤄 단일 책임 원칙을 위반한다.
- Android 프로토타입 `ReadViewModel`은 파일, 저장, 검색, 번역, quota, 뷰어와 내보내기를 함께 다뤄 단일 책임 원칙을 위반한다.
- 두 구현 모두 화면 상태가 구체 저장소와 네트워크 구현에 직접 의존해 의존성 역전 원칙을 위반한다.
- CMP/KMP에서는 첫 슬라이스에 필요한 순수 상태, 플랫폼 파일 선택, 공통 UI만 분리하고 미사용 계층은 만들지 않는다.

## 2026-09-22 정상화 동작 기준

현재 KMP 사전 중심 앱을 기준으로 한다. Flutter 문장 번역과 저장형 단어장을 새로 복원하지 않는다.

- TXT 열기, 문장 이동, 사용자 번역 입력, 재실행 복원은 같은 문서 ID와 문장 인덱스를 사용한다.
- 리더 하단 `입력`은 사용자 번역 입력창에 초점을 옮긴다. 입력은 문장별로 자동 저장한다.
- 드로어의 `번역문 내보내기`는 입력한 사용자 번역을 시스템 저장 창으로 내보낸다. 취소하면 리더 데이터는 유지한다.
- 읽기 화면은 기본 화면의 문장 위치, 진행률, 북마크와 타이머를 공유한다. 읽기 화면에서 연 설정과 북마크를 닫으면 읽기 화면으로 돌아간다.
- `사전 검색`은 빈 검색창으로 시작한다. 본문 아래 단어 목록은 가로 스크롤로 모든 토큰에 접근한다.
- 사전 결과 없음에서만 번역을 요청한다. 검색어 변경 또는 모달 닫기 이후 도착한 이전 결과·오류는 무시한다.
- 번역 결과는 `DeepL 번역 결과`로 표시하고 위키낱말사전 결과와 구분한다.
- 번역 사용량은 서버 성공 응답으로 갱신하고, 오류 대화상자에서 같은 요청을 다시 시도할 수 있다.
- Firebase 설정이 없더라도 오프라인 리더와 사전은 사용할 수 있다. 번역 요청 시 설정 미준비 오류를 표시한다.
- iOS는 CocoaPods 통합으로 빌드한다. `GoogleService-Info.plist`는 로컬에만 두고 저장소에서 제외한다.

검증 결과와 플랫폼별 남은 작업은 `docs/normalization-verification.md`에 기록한다.
